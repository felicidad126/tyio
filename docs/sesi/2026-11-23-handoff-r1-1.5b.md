**Koreksi untuk PostgreSQL 18:** perintah R0 membuat cluster **SQL_ASCII / locale C** (bawaan container),
sedangkan CI memakai UTF8. Buat cluster dengan:

```bash
pg_createcluster 18 main --port 5432 --encoding UTF8 --locale C.UTF-8 --start -- --auth-local=trust --auth-host=scram-sha-256
```

Cek: `su postgres -c "psql -Atc \"SELECT datname, pg_encoding_to_char(encoding) FROM pg_database\""` harus
UTF8 semua. Container lama yang sudah SQL_ASCII: `pg_dropcluster 18 main --stop`, buat ulang, lalu buat
peran dan database seperti di R0. Setelah container dimulai ulang: `pg_ctlcluster 18 main start`.

## Jebakan baru (sesi ini; jangan diulang)

- **Database lokal SQL_ASCII ≠ CI (UTF8).** Gejala: nama berkas lampiran "Lokasi – ATM.png" → galat 500
  hanya di lokal. Koreksi perintah setup di atas.
- **`[:cntrl:]` di regex PostgreSQL bergantung locale**; pakai rentang eksplisit
  (`[/\\\x01-\x1f\x7f-\x9f]`) di CHECK.
- **multer membaca nama berkas sebagai latin1** secara bawaan → set `defParamCharset: 'utf8'` (sudah di
  `ticket-actions.controller.ts`).
- **vitest tidak memeriksa tipe.** Uji bisa hijau sementara `pnpm build` gagal pada berkas uji (terjadi di
  `5bbc57c`). Jalankan `pnpm build` sebelum setiap commit.
- **Trigger BEFORE berjalan menurut abjad nama.** Trigger yang mengisi kolom yang dibaca `assign_number`
  harus bernama lebih awal (`apply_refs` < `assign_number` di `trouble_tickets`; diuji mutasi).
- **Penolakan berlapis menutupi penjaga yang rusak.** Uji yang hanya mencocokkan "sudah ditutup" tetap
  hijau walau penjaga TT dirusak, karena penjaga linimasa ikut menolak. Cocokkan pesan penjaga yang
  diuji.
- **Mutasi yang membuat galat sintaks terlihat "merah" palsu** ("Tests no tests"). Ganti teks dengan
  ekspresi sah (mis. `,` atau `false`), dan pastikan ringkasan "N failed | M passed".
- **Tata letak di CI bisa beberapa px lebih lebar dari lokal** (font berbeda): uji ponsel `ticket-create`
  lulus lokal, merah di CI (7 px). Tombol di judul (`PageHeader.vue`) kini `flex-wrap`.
- **Jawaban API yang lebih lama bisa menimpa yang lebih baru** pada daftar yang dimuat ulang saat saringan
  berubah. Pakai nomor permintaan (`latest`) seperti di `TicketListPage.vue`/`TroubleTicketList.vue`.
- **Penyelarasan alamat → kotak cari bisa menimpa ketikan yang belum terkirim** (debounce). Lihat flag
  `typing` di `TicketListPage.vue`.
- **GPG di scratchpad gagal** ("can't connect to the gpg-agent"): jalur soket > 108 karakter. Pakai
  `GNUPGHOME` lewat symlink pendek (sesi ini: `/tmp/claude-0/gk`).
- **Tangkapan layar via `file://` di Playwright diblokir**; ambil tangkapan setinggi layar langsung
  (`fullPage: false`) bila halaman terlalu panjang.
- Mengubah migrasi yang belum dirilis setelah dijalankan di database dev: jalankan
  `node dist/db/migrate.js down` lalu `up` **setelah build berhasil** (build gagal = `dist` lama).

Paling berat dulu:
- **Pemeriksaan otomatis:** tidak ada hook yang menjalankan `pnpm build` (cek tipe uji) sebelum commit.
  Usul: hook pre-commit atau langkah `pnpm build` di skrip `test`. Uji mutasi masih skrip sementara
  (hilang tiap sesi) — usul `apps/api/test/mutasi/` berisi skrip + daftar per langkah (sudah diusulkan
  di handoff 1.3, belum dikerjakan).

  environment cloud (Node 26 + PostgreSQL 18 UTF8 + `pg_ctlcluster start`).
- **Akses informasi:** log CI lengkap hanya lewat URL unduhan (`get_job_logs` dengan
  `return_content: false` → `curl`, ±95 MB); dipakai untuk menemukan penyebab run #119.
